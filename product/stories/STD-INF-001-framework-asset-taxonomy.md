# STD-INF-001 – Framework Asset Taxonomy

## Business Value

Provide stable classification and identity rules so people and systems can locate, relate, and govern framework assets consistently.

## Scope

Define supported asset types, identifier prefixes, ownership, metadata, lifecycle, relationships, storage, and representation.

## Requirements

- Cover every asset type named in the sprint specification.
- Require globally unique identifiers that survive file moves.
- Distinguish current asset types from future capabilities.

## Required Deliverable

[Framework Asset Taxonomy](../../docs/framework/FRAMEWORK_ASSETS.md)

## Dependencies

- [Release REL-004](../releases/REL-v0.4.md)
- [Epic EPIC-001](../epics/EPIC-001-enterprise-standards-framework.md)
- [Sprint SPR-004-001B](../sprints/SPR-004-001B-standards-foundation.md)

## Acceptance Criteria

- Purpose, prefix, owner, metadata, lifecycle, relationships, location, and machine considerations are defined for each asset.
- Required identifier examples are included.

## Validation Requirements

Review identifier uniqueness, naming consistency, links, and alignment with repository structure.

## Definition of Ready

Asset scope, identifier examples, and target path are approved.

## Definition of Done

The deliverable meets acceptance criteria, passes available checks, and is ready for Product Owner review.

## Product Owner Approval

Product Owner approval is required before this story is complete.
